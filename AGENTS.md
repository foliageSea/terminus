# AGENTS.md

## Commands

- Use pnpm; CI uses pnpm 10, Node 22, and `pnpm install --frozen-lockfile`.
- `pnpm install` triggers `electron-builder install-app-deps` for Electron native deps including `node-pty`.
- Start dev app with `pnpm dev` (`electron-vite dev`). Preview a built app with `pnpm start`.
- Validation shortcuts: `pnpm lint`, `pnpm format:check`, `pnpm typecheck`, `pnpm typecheck:node`, `pnpm typecheck:web`, `pnpm build`.
- There is no test script in `package.json`; use lint/format/typecheck/build as verification unless you add tests.
- Packaging commands are `pnpm build:win`, `pnpm build:mac`, `pnpm build:linux`; each runs typecheck and `electron-vite build` first.
- GitHub Actions currently builds Windows x64 releases with `pnpm build:win -- --x64`; macOS is present but commented out. CI runs only on tag push or manual dispatch and does **not** run lint/typecheck, so run them yourself before committing.
- If a `pnpm <script>` call aborts with `ERR_PNPM_ABORTED_REMOVE_MODULES_DIR_NO_TTY` (pnpm thinks `node_modules` is out of sync, wants to reinstall, and has no TTY to confirm), bypass pnpm and call the tool directly: `node_modules/.bin/tsc.cmd --noEmit -p tsconfig.node.json --composite false`, `node_modules/.bin/vue-tsc.cmd --noEmit -p tsconfig.web.json --composite false`, `node_modules/.bin/eslint.cmd .`.

## Project Shape

- This is a single-package Electron-Vite app with three TS targets: `src/main`, `src/preload`, `src/renderer/src`, plus a shared layer in `src/shared`.
- Main process entry is `src/main/index.ts`; renderer entry is `src/renderer/src/main.ts`; preload API/types are `src/preload/index.ts` and `src/preload/index.d.ts`.
- `src/shared/shortcuts.ts` is imported by both main (validation/normalization) and renderer (key matching/UI). Put anything both sides need there instead of duplicating it.
- Renderer aliases `@/*` and `@renderer/*` both map to `src/renderer/src/*` in `electron.vite.config.ts` and `tsconfig.web.json`; `src/shared` is currently imported through relative paths.
- UI is Vue 3 + Tailwind CSS 4 + `reka-ui` + `lucide`; there is no component framework. `src/renderer/src/components/ui/*` are hand-written wrappers: some re-export `reka-ui` primitives directly, the rest are small `.vue` files styled by the `.ui-*` classes in `assets/main.css`. `components.json` marks the project as shadcn-vue, but these components were not generated by the shadcn CLI (no `class-variance-authority`, no Tailwind variant classes) — match the existing style rather than running the CLI.
- `App.vue` mounts `TerminalWorkspace`, which owns tab/split pane state.
- Main process IPC is split under `src/main/ipc`; terminal logic is in `src/main/terminal`, settings persistence in `src/main/settings`, window creation/lifecycle in `src/main/app`, and cross-module helpers in `src/main/shared`.

## Terminal Integration

- The terminal backend lives in the main process and uses `node-pty`; renderer code must go through `window.api.terminal` exposed by preload.
- Keep IPC channel names/types synchronized across `src/main/ipc/*`, `src/preload/index.ts`, `src/preload/index.d.ts`, and the renderer-side copies in `src/renderer/src/types/terminal.ts`.
- Terminal pane IDs are renderer-generated IDs used as keys in the main-process pty map; closing tabs/panes should call `window.api.terminal.kill` to avoid orphaned ptys.
- On Windows the spawned shell is `powershell.exe -NoLogo -NoExit -Command <cwd prompt hook>`; non-Windows uses `process.env.SHELL || '/bin/bash'`.
- Terminal cwd is tracked from PTY output (OSC 633 on Windows, OSC 7 as fallback) and stored on pane nodes; new splits inherit the source pane `cwd`.
- PTY output is chunked at 100 KB with byte-level backpressure: the renderer must keep calling `window.api.terminal.ackData` after writing to xterm, otherwise the pty stays paused.
- On Windows a dead PTY is recreated automatically with exponential backoff (at most 5 consecutive attempts, counter reset after 10s of uptime). `TerminalState.closed` is set by every kill path so a pending restart cannot resurrect a closed pane — keep that invariant.
- All external URL opening goes through `isSafeExternalUrl` / `openExternalUrl` in `src/main/shared/externalUrl.ts` (http/https only). Do not call `shell.openExternal` directly.

## Style And Build Quirks

- `.gitattributes` forces LF for every text file and `.editorconfig` also requires LF. Keep it that way: CRLF makes `pnpm lint` and `pnpm format:check` fail with thousands of `Delete ␍` warnings.
- `.agents/` holds third-party agent skill content validated by `skills-lock.json`; Prettier ignores it on purpose. Do not reformat it.
- Prettier config is non-default: single quotes, no semicolons, print width 100, no trailing commas.
- ESLint requires Vue SFC `<script>` blocks to use `lang="ts"`; `vue/multi-word-component-names` and `vue/require-default-prop` are disabled.
- `electron-builder.yml` unpacks `node_modules/**/node-pty/**`; preserve this when touching packaging because `node-pty` is native.
- `electron-builder.yml` excludes `.env*`, source, tsconfig files, README, and `pnpm-lock.yaml` from packaged files.
- Build output directories `out` and `dist` are ignored by ESLint; do not edit generated output.
- `package.json`'s `pnpm.onlyBuiltDependencies` is no longer read by pnpm 10; the effective build allowlist is `allowBuilds` in `pnpm-workspace.yaml`.
